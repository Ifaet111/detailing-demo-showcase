# Публикация OFFSET

Публикуйте **содержимое `dist/`**, сохраняя вложенные папки и служебные файлы. В корне публикации должен лежать `index.html`. Node.js нужен для сборки, но не требуется на хостинге готового сайта.

Текущая публикация: https://ifaet111.github.io/detailing-demo-showcase/. На GitHub `offset-source` содержит исходники, `main` — статическую сборку для Pages. Настройка публикации `main / (root)` сохранена. Для обновления исходников работайте в `offset-source`, выполните сборку, затем перенесите содержимое `dist/` в ветку `main` и отправьте обе ветки. Не отправляйте исходную HTML-разметку вместо собранной: сборка добавляет SEO-метаданные.

## 1. Указать адрес

Адрес GitHub Pages уже настроен. При переносе на другой хостинг измените базовый URL. Можно использовать адрес хостинга без собственного домена. Для размещения в подпапке укажите полный адрес вместе с этой подпапкой.

Есть два равнозначных способа:

- Вписать настоящий HTTPS-адрес в `siteUrl` внутри `src/shared/config.js`.
- Установить переменную окружения `SITE_URL` перед сборкой; она имеет приоритет над конфигурацией.

Пример для PowerShell без подставного домена:

```powershell
$env:SITE_URL = Read-Host 'Введите окончательный HTTPS-адрес сайта'
npm run check
npm run build
```

Контакт уже настроен: `andrewvasilen4@gmail.com`. Секретов и API-ключей в проекте нет.

## 2. Проверить сборку

```sh
npm run preview
```

Откройте `http://127.0.0.1:4187`. Проверьте главную, все пять проектов, мобильное меню, выбор параметров и формирование обращений. Проверьте страницу ошибки через несуществующий адрес. Остановите сервер сочетанием `Ctrl+C`.

Сборка добавляет Open Graph/Twitter-метаданные, `robots.txt`, `.nojekyll`, `_headers` и сохраняет `404.html`. Canonical, `og:url` и `sitemap.xml` формируются, когда указан настоящий публичный URL. После смены адреса выполните сборку заново.

## 3. Выбрать способ размещения

### Netlify

Для ручной публикации создайте проект через ручную загрузку и перетащите папку `dist/`. Загружайте уже собранные файлы. Если Netlify сначала назначил новый адрес, внесите его в `SITE_URL`, пересоберите и загрузите результат повторно.

При подключении Git-репозитория задайте корневую папку этого проекта, build command `npm run build`, publish directory `dist`, Node.js 20+ и переменную `SITE_URL`. Проверку `npm run check` можно добавить перед сборкой: `npm run check && npm run build`.

Порядок загрузки и параметры сборки: [официальная инструкция Netlify](https://docs.netlify.com/deploy/create-deploys/), [build settings](https://docs.netlify.com/build/configure-builds/overview/).

### Cloudflare Pages

Создайте Pages-проект с **Direct Upload**, загрузите папку `dist/` или архив её содержимого и запустите публикацию. После назначения публичного адреса укажите его в конфигурации и загрузите новую сборку. Для обновления загружайте новый `dist/` в тот же проект.

Для проекта с Git-интеграцией: framework preset — без фреймворка, build command — `npm run build`, output directory — `dist`, Node.js 20+, переменная `SITE_URL` — окончательный URL.

Подробности двух режимов: [Cloudflare Pages Direct Upload](https://developers.cloudflare.com/pages/get-started/direct-upload/). Direct Upload и Git-интеграция — разные варианты создания проекта; выберите подходящий заранее.

### GitHub Pages

1. Создайте или выберите репозиторий для публикации. Новая реализация не изменяла исходный репозиторий OFFSET автоматически.
2. Укажите в `SITE_URL` полный будущий адрес Pages, включая путь репозитория, если он есть. Соберите проект.
3. Поместите **содержимое `dist/`** в корень отдельной ветки публикации, например `gh-pages`, и отправьте её в репозиторий. Не переносите только саму внешнюю папку `dist`.
4. В репозитории откройте **Settings → Pages → Build and deployment → Deploy from a branch**, выберите эту ветку и папку **/(root)**, сохраните.
5. Сохраните `.nojekyll` в корне ветки. Готовый `404.html` также должен остаться в корне: GitHub Pages использует его для отсутствующих страниц.

Пути сайта относительные, поэтому главная и демо поддерживают размещение в подпапке репозитория. Canonical и sitemap должны содержать тот же базовый адрес. Для автоматической сборки можно вместо ветки настроить GitHub Actions и публиковать артефакт из `dist/`.

Источники: [выбор источника публикации GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site), [страница 404](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-custom-404-page-for-your-github-pages-site), [GitHub Actions для Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

### Другой статический хостинг

Загрузите содержимое `dist/` в web root. Включите HTTPS, выдачу `index.html` для каталогов и пользовательский `404.html` с HTTP-статусом 404. Не настраивайте перенаправление всех неизвестных адресов на главную: это обычный многостраничный сайт. `_headers` применяется поддерживающими его платформами; на другом сервере при желании перенесите эти заголовки в настройки хостинга.

## Формы после публикации

OFFSET использует `mailto:andrewvasilen4@gmail.com`. Отправку подтверждает сам посетитель в почтовом приложении. Копирование и скачивание текста работают как запасной способ; при недоступном Clipboard API форма выделяет текст для ручного копирования.

Демо не отправляют данные, не бронируют машины, не подтверждают участие и не записывают в сервис. Если позже понадобится серверная отправка, сначала подключите выбранный сервис и добавьте соответствующие сведения об обработке данных. Для текущей версии такой сервис не требуется. В проект не добавлены вымышленные реквизиты, адреса, политика компании или утверждения о юридическом статусе. Аналитика и cookies не подключены.

## После загрузки

Проверьте опубликованный HTTPS-адрес, прямой вход в каждое демо и возврат к OFFSET. Откройте несуществующий вложенный URL, убедитесь в корректной странице 404 и ссылке домой. Проверьте письмо на настоящий адрес, `robots.txt`, `sitemap.xml` и canonical. Для нового домена повторите сборку с новым `SITE_URL`.
